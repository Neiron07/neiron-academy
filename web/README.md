# Neiron Academy — фронтенд (v1)

Лендинг + 4 личных кабинета поверх бэкенда из корня репозитория. Next.js 15, App Router,
TypeScript strict, Tailwind v4 (только 7 фирменных токенов), TanStack Query.

## Запуск

```bash
cd web
cp .env.example .env.local     # BACKEND_URL должен указывать на запущенный бэкенд
npm install
npm run dev                     # http://localhost:3000
```

Бэкенд запускается отдельно из корня репозитория (`npm run dev`, порт 3001).

## Архитектура авторизации

JWT бэкенда никогда не попадает в браузер. `app/api/proxy/auth/[...path]/route.ts` вызывает
бэкенд, кладёт токен в httpOnly-куку (`neiron_token`) и роль в отдельную куку (`neiron_role`),
наружу отдаёт только профиль. `app/api/proxy/[...path]/route.ts` — общий прокси для всех
остальных ручек: достаёт токен из куки и подставляет `Authorization: Bearer`.
`middleware.ts` — это UX-редирект по роли, а не граница безопасности: реальные права
на каждый запрос проверяет бэкенд.

## Структура

```
app/
  page.tsx              лендинг
  login/                вход, 3 вкладки
  app/student|parent|teacher|admin/   кабинеты под auth
  api/proxy/            прокси-слой к бэкенду
components/
  ui/                   кнопка, поле, карточка, шит, тост, скелетон, статус-бейдж
  mascot/               SVG-маскот, 5 стадий эволюции
  landing/ auth/ teacher/ parent/ admin/   экраны по разделам
lib/
  types.ts              типы ответов API — зеркало src/routes/*.ts бэкенда
  api.ts, auth-client.ts клиентские обёртки над /api/proxy
```

## Известные пробелы в API (не реализовано, потому что нечем)

Бэкенд почти не трогали, как просили — согласованные исключения:
- `GET /api/public/courses` теперь отдаёт `id` курса (был только `slug`), иначе форма
  создания группы в админке не могла передать `course_id`, который требует бэкенд.
- Родитель входит по телефону + PIN, как ученик по логину + PIN: добавлен
  `POST /api/auth/parent/login`, генерация `pin_hash` при создании нового родителя
  в `POST /admin/students`, и `POST /api/admin/users/:id/reset-pin` — админ сбрасывает
  PIN и ученику, и родителю. Старый вход по коду WhatsApp (`/parent/request-code`,
  `/parent/verify`) оставлен в бэкенде нетронутым на случай, если понадобится вернуть.

Ниже — места, где фронтенду по-прежнему не хватает ручки; решения временные:

1. **Список преподавателей.** Нет `GET /admin/teachers` — при создании группы нельзя
   выбрать преподавателя из списка. Группа создаётся без `teacher_id`, назначить его
   сейчас неоткуда (нет и `PATCH` на группу).
2. **Список домашних заданий по группе.** Нет `GET /homework?group_id=`. После создания
   задания страница проверки открывается по свежему `id` из ответа, но future-визит
   «посмотреть все задания группы» показать нечем.
3. **Телефон в зоне риска.** `v_at_risk` отдаёт только имя ученика, без контакта родителя —
   кнопка на дашборде ведёт в поиск по разделу «Ученики» вместо прямого `tel:`/WhatsApp.
4. **Слот кастомизации маскота.** `POST /me/equip` принимает `slot`, но ни `shop_items`,
   ни инвентарь не говорят, для какого слота предназначен предмет — сейчас ученик выбирает
   слот вручную при надевании.

## Плейсхолдер-контент

`lib/site-content.ts` — цены, отзывы, преподаватели, адрес. Это примерные данные для
демонстрации лендинга, замените на реальные перед запуском в прод.
