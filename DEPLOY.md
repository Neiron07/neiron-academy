# Деплой

Бэкенд (Fastify, `/`) — на **Render**. Фронтенд (Next.js, `/web`) — на **Vercel**.
Render, а не что-то serverless — потому что в бэкенде живут фоновые задачи на `croner`
(раскатка расписания, очередь уведомлений), а им нужен постоянно работающий процесс,
а не функция, которая просыпается на запрос.

---

## 1. Бэкенд → Render

1. render.com → **New +** → **Blueprint** → подключить репозиторий `Neiron07/neiron-academy`.
   Render сам найдёт `render.yaml` в корне и предложит создать сервис `neiron-backend`.
2. План по умолчанию — **Free**. Это ок для проверки, но у free-плана есть sleep после
   простоя — тогда `croner`-задачи (напоминания, раскатка уроков) не сработают вовремя,
   пока сервис спит. Для реальной работы школы переключите на **Starter** в настройках
   сервиса, когда будете готовы.
3. После создания сервиса — вкладка **Environment**, заполнить вручную (они помечены
   `sync: false` в `render.yaml`, то есть в репозиторий не попадают):

   | Переменная | Значение |
   |---|---|
   | `DATABASE_URL` | из вашего `.env` — transaction pooler, порт 6543 |
   | `DIRECT_URL` | из вашего `.env` — session pooler, порт 5432 |
   | `JWT_SECRET` | из вашего `.env` (тот же — иначе все текущие сессии слетят) |
   | `BRANCH_ID` | `00000000-0000-0000-0000-000000000001` |
   | `APP_URL` | заполните после шага 2 (домен Vercel) — временно можно `http://localhost:3000` |
   | `GREEN_API_ID` / `GREEN_API_TOKEN` | если подключали WhatsApp-рассылку через Green API |
   | `ADMIN_NOTIFY_PHONE` | `77471655391` |

   Это та же Supabase-база, что и в локальной разработке — миграции уже применены,
   повторно накатывать не нужно. Если захотите отдельную прод-базу — сначала
   `npm run migrate` и `npm run seed` с `DIRECT_URL`, указывающим на неё.

4. Deploy. Проверка: `https://<ваш-сервис>.onrender.com/health` → `{"ok":true}`.

---

## 2. Фронтенд → Vercel

1. vercel.com → **Add New** → **Project** → импортировать тот же репозиторий.
2. **Root Directory** — обязательно указать `web` (репозиторий монорепо: бэкенд в
   корне, фронтенд в `/web`). Framework Preset определится сам — Next.js.
3. **Environment Variables**:

   | Переменная | Значение |
   |---|---|
   | `BACKEND_URL` | URL бэкенда с Render из шага 1, например `https://neiron-backend.onrender.com` |
   | `NEXT_PUBLIC_WHATSAPP_PHONE` | `77471655391` |
   | `NEXT_PUBLIC_META_PIXEL_ID` | необязательно, если подключаете Meta Pixel |

4. Deploy. Vercel выдаст домен вида `neiron-academy.vercel.app`.

---

## 3. Связать домены

Вернитесь в Render → Environment → обновите `APP_URL` на реальный домен Vercel
(`https://neiron-academy.vercel.app`, без слэша на конце) и передеплойте сервис —
это значение бэкенд использует для CORS. Строго говоря, браузер никогда не обращается
к бэкенду напрямую (всё идёт через прокси Next.js), так что это скорее подстраховка,
но лучше выставить верно.

Свой домен (например, `neironacademy.kz`) подключается штатно в настройках Vercel
(Domains) для фронтенда; Render аналогично умеет custom domains для API, если он вам
нужен на отдельном поддомене вроде `api.neironacademy.kz`.

## Чек-лист перед тем, как пускать реальных пользователей

- [ ] Пароль базы в Supabase сменён (старый уже "засветился" в истории работы над проектом)
- [ ] `JWT_SECRET` на Render — длинный случайный, не дефолтный из `.env.example`
- [ ] Render-план — не Free, если фоновые задачи должны работать надёжно
- [ ] `APP_URL` на Render указывает на реальный домен фронтенда
- [ ] Тестовые аккаунты (Amir Testov и т.д.) удалены или помечены как тестовые
